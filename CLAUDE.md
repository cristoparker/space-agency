# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Space Agency is a Unity **6000.6.5f1** (URP 17.6, new Input System, TextMeshPro, uGUI) management game. The player runs a space agency, takes contracts, builds facilities, designs rockets, and launches them. All game code is in `Assets/Scripts`, which compiles into `Assembly-CSharp` (there are no `.asmdef` files and no tests). The `.csproj`/`.slnx` files are generated by Unity and gitignored.

Scenes, in build order: `Assets/Scenes/1. Main Menu.unity` → `2. Game.unity` (the base, where most of the game happens) → `3. Flight.unity`. The flight scene is loaded additively on top of the Game scene by `FlightSceneLauncher` (`Rocket/FlightScene.cs`), so game state stays loaded underneath.

## Building and verifying

There is no command-line build or test setup. Compile errors and play testing happen in the Unity Editor (or through the `unity:unity-cli` skill against a running Editor). Editor scripts live in `Editor/` subfolders next to the systems they configure.

## Scenes and assets are generated by editor scripts

Much of the scene content and data assets are **built by idempotent editor menu commands, not edited by hand**. When you change one of these systems, change the setup script and re-run it instead of patching the `.unity` file:

| Menu | Script | Builds |
|---|---|---|
| Tools / Space Agency / Rebuild Level | `Base/Editor/LevelSetup.cs` | The whole base in `2. Game.unity`: terrain, procedural roads, Blender site models, Holotna nature prefabs, plots P1–P5, and `Resources/FacilityCatalog` |
| Tools / Space Agency / Setup Rocket Builder | `Rocket/Editor/RocketBuilderSetup.cs` | `Data/Parts/PartLibrary.asset` from `parts-catalog.json` and part FBXs/icons, the builder window, and `DeploymentManager` |
| Tools / Space Agency / Setup Game UI (+ Apply Apple Glass Style) | `UI/Editor/GameUISetup.cs` | `Resources/UITheme.asset`, the HUD in Game, menu screens in Main Menu, build scene list |
| Tools / Space Agency / Setup Visual Effects | `Rendering/Editor/VisualEffectsSetup.cs` | Post-processing volume, god rays renderer feature, sun settings |
| Tools / Missions / Import From JSON... | `Missions/Editor/MissionJsonImporter.cs` | `MissionDefinition` assets in `Data/Missions/Definitions` + `MissionDatabase` from `missions.json` (keyed by id) |

## Art pipeline (`ArtSource/`)

Every model is low-poly and procedural, generated by Python scripts run in Blender (headless `blender -b --python ArtSource/<script>.py`, or through the Blender MCP). Scripts share helpers by `exec`-ing the top section of `build_base.py` / `build_site.py`. Outputs go to `Assets/Assets/Models/...` (FBX plus a palette texture) and, for parts, `Assets/Data/Parts/parts-catalog.json`, which holds the gameplay stats for every part. Conventions: metres, +Z up in Blender (+Y in Unity), origin at the bottom centre of each part, front faces −Y. After re-exporting, run the matching Unity setup menu so assets/libraries pick up the changes. Other scripts here generate icons, road textures, and music.

## Runtime architecture

- **Managers are singletons** (`public static X Instance`) placed in the Game scene: `GameClock`, `MissionManager`, `DeploymentManager`, base/facility simulation (`BaseSim`), `ResourceFlow`, `TrafficManager`, etc. Systems communicate through C# events on these (`Changed`, `MissionStarted`, `MissionEnded`, `SpeedChanged`...). `MissionManager` is the only owner of contract state.
- **Time:** `GameClock` starts from the real current Dhaka time (GMT+6) and runs fast. `Time.timeScale` is capped at `maxTimeScale` (16), while higher game speeds only advance the clock. Simulation that must respect fast-forward should use `GameClock.GameDeltaSeconds` / `GameTime`, not `Time.deltaTime`. Popups and cutscenes pause the clock.
- **Persistence:** everything is saved in **PlayerPrefs** under `SpaceAgency.*` keys (JSON through `JsonUtility`): agency profile (`Agency` static class, shared between Main Menu and Game), base, deployment, rocket designs, client trust, settings. There is no other save system. When changing a serialized class, keep old saves loading (existing loaders `try/catch` and fall back to defaults).
- **Enter Play Mode without domain reload:** static fields persist between Play sessions. Any class with static state must expose `ResetStatics()` and be registered in `UI/StaticReset.cs`.
- **UI is built in code**, not authored in prefabs. `UIKit` has helpers on a **640×360** reference canvas (`UIKit.Shrink` scales panels, except the top bar and dock). Colours, fonts, and glass materials come from `UITheme.Current` (`Resources/UITheme`). Glass materials: `glass` only for top-level panels (it blurs the scene), `flat`/`frost` for anything inside them. `HudController` builds the HUD and opens one panel at a time. `Hud.Toast(msg)` shows a global message line.
- **Rocket flow:** `RocketBuilderUI` edits a `RocketDesign` (bottom-to-top stack + attachments, parts from `PartLibrary`) → `RocketConstruction` builds it over game time → `DeploymentManager` puts it on the pad with a launch date and contract → `LaunchSequence` cutscene → `FlightSimulator` (thrust/fuel/drag/gravity on the actual design) produces a `FlightProfile` → `FlightOutcome` decides the result → flight scene shows it on the office monitor → mission result returns to `MissionManager`.
- **Missions:** `MissionDefinition` (ScriptableObject) → `MissionInstance` at runtime with `Objectives`. `RandomEvents` adds about three mission events and one client event per contract (benefit/cost/risk choices, shown through `EventCard`/`ImpactCard`). `GlobalContracts` handles client trust.
- **Rendering:** custom toon shaders under `Assets/Shaders` (`SpaceAgency/Toon/*`, sky, water, outline, UI glass, god rays through `GodRaysFeature`). Renderer/volume assets are in `Assets/Settings`.
